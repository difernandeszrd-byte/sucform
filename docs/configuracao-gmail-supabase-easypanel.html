Parte 1 — Gmail (Senha de App)

Configuração do envio de e-mail via SMTP usando Senha de App do Google

1.1 — Visão Geral do Serviço

O sistema utiliza o SMTP do Gmail com Senha de App para enviar e-mails de confirmação de inscrição. Ao contrário do OAuth2 (que exige renovação periódica de tokens), a Senha de App é uma credencial estável que não expira automaticamente.

ParâmetroValor
Servidor SMTPsmtp.gmail.com
Porta587 (STARTTLS — mais compatível)
AutenticaçãoUsuário + Senha de App (16 caracteres)
TLSObrigatório (requireTLS: true)
BibliotecaNodemailer (Node.js)

1.2 — Pré-requisitos

Conta Google ativa

A conta difernandeszrd@gmail.com deve estar ativa e acessível.

Verificação em 2 etapas (2FA) ativada

A Senha de App só pode ser gerada se a 2FA estiver habilitada. Acesse: Conta Google → Segurança → Verificação em duas etapas.

Acesso menos seguro desativado

O sistema moderno usa Senha de App, que é mais segura que "acesso de apps menos seguros" (que o Google desativou em 2024).

1.3 — Gerando a Senha de App no Google

Acessar o gerenciador de Senhas de App

Vá para: https://myaccount.google.com/apppasswords
Faça login com a conta difernandeszrd@gmail.com.

Criar nova senha

No campo "Nome do app", digite um nome identificador (ex: cadform ou sucform-easypanel) e clique em Criar.

Copiar a senha gerada

O Google exibirá uma senha de 16 caracteres formatada em 4 grupos de 4 letras (ex: dwou hzqp lxqj nfgs).
⚠️ Importante: Remova os espaços antes de usar no código!

Salvar com segurança

Esta senha só é exibida uma vez. Guarde-a em local seguro. Se perder, gere uma nova.

⚠️
Atenção: Remova os espaços da senha! O Google exibe a senha com espaços para facilitar a leitura, mas o Nodemailer precisa da senha sem espaços para autenticar via SMTP. Use dwouhzqplxqjnfgs e não dwou hzqp lxqj nfgs.

1.4 — Configurando no Código (send-email.js)

O arquivo api/send-email.js contém a lógica de envio. As credenciais são carregadas via variáveis de ambiente com fallback hardcoded (mesma abordagem do Supabase):

// api/send-email.js — Configuração do transporter Nodemailer
const gmailUser     = process.env.GMAIL_USER         || 'difernandeszrd@gmail.com';
const gmailAppPass  = process.env.GMAIL_APP_PASSWORD || 'dwouhzqplxqjnfgs';
const fromName      = process.env.GMAIL_FROM_NAME    || 'Semana Universitária Cajuruense';

const transporter = nodemailer.createTransport({
  host: 'smtp.gmail.com',
  port: 587,
  secure: false,     // STARTTLS — NÃO usar true aqui
  requireTLS: true,
  auth: { user: gmailUser, pass: gmailAppPass },
  tls: { rejectUnauthorized: false } // necessário em alguns ambientes
});
ℹ️
Por que porta 587 e não 465? A porta 465 (SSL direto) apresentou erro de certificado self-signed em ambiente de desenvolvimento Windows com antivírus. A porta 587 (STARTTLS) funciona corretamente em todos os ambientes testados: Windows local, EasyPanel/Linux e containers Docker.

1.8 — Diagnóstico de Erros Comuns

Erro: Username and Password not accepted

❌
Causa: Senha de App incorreta, com espaços ou expirada.
Solução: Acesse myaccount.google.com/apppasswords, revogue a senha atual e gere uma nova. Certifique-se de copiar sem espaços.

Erro: self-signed certificate in certificate chain

⚠️
Causa: Antivírus ou proxy de rede interceptando a conexão SSL (comum no Windows).
Solução: Usar porta 587 com tls: { rejectUnauthorized: false }.

Erro: GMAIL_USER / GMAIL_APP_PASSWORD não configuradas

❌
Causa: Variáveis de ambiente não disponíveis em runtime no EasyPanel.
Solução: Usar o padrão process.env.VAR || 'fallback' no código. Variáveis de build do Nixpacks não são automaticamente injetadas no processo Node.js em runtime.

Erro: invalid_grant: Token has been expired or revoked

❌
Causa: Este erro ocorre apenas com OAuth2 (não com Senha de App). O Refresh Token expirou.
Solução: Migrar para Senha de App (já implementado). OAuth2 não deve mais ser usado neste projeto.

2.5 — Configuração da Tabela no Banco

No painel do Supabase, acesse Table Editor → New Table ou use o SQL Editor:

-- SQL para criar a tabela de inscritos
CREATE TABLE inscritos (
  id              uuid          DEFAULT gen_random_uuid() PRIMARY KEY,
  nome            text          NOT NULL,
  email           text          NOT NULL,
  cpf             text,
  data_nascimento date,
  telefone        text,
  cidade_estado   text,
  bairro          text,
  chefe_de_equipe boolean       DEFAULT false,
  created_at      timestamptz   DEFAULT now()
);

-- Índice para busca por e-mail
CREATE INDEX idx_inscritos_email ON inscritos (email);
-- Índice para busca por CPF
CREATE INDEX idx_inscritos_cpf   ON inscritos (cpf);

2.6 — Políticas de Segurança (RLS — Row Level Security)

O Supabase usa RLS para controlar o acesso. Configure as políticas conforme abaixo:

-- Habilitar RLS na tabela
ALTER TABLE inscritos ENABLE ROW LEVEL SECURITY;

-- Política: qualquer pessoa pode INSERIR (formulário público)
CREATE POLICY "Inscrições públicas permitidas"
  ON inscritos FOR INSERT
  TO anon
  WITH CHECK (true);

-- Política: apenas autenticados podem SELECIONAR (painel admin)
CREATE POLICY "Leitura restrita ao admin"
  ON inscritos FOR SELECT
  TO authenticated
  USING (true);

-- Alternativa: permitir leitura pública (se o painel usa só senha client-side)
CREATE POLICY "Leitura pública"
  ON inscritos FOR SELECT
  TO anon
  USING (true);
ℹ️
Política recomendada para este projeto: Como o painel admin usa senha client-side (não autenticação Supabase), mantenha a leitura pública (anon). O acesso é protegido pelo painel que solicita a senha cajuru@2026.

2.7 — Diagnóstico de Erros Comuns

Erro: Failed to fetch / CORS

❌
Causa: URL do Supabase incorreta ou projeto pausado.
Solução: Verifique se o projeto está ativo no painel Supabase. Projetos gratuitos pausam após 90 dias sem acesso. Clique em Restore no painel.

Erro: new row violates row-level security policy

⚠️
Causa: A política RLS não permite INSERT para usuários anônimos.
Solução: Adicionar a política de INSERT para anon conforme o SQL acima, ou desabilitar RLS temporariamente para testes.

Erro: Invalid API key

❌
Causa: A chave foi resetada no painel Supabase ou é a chave errada (Secret vs Publishable).
Solução: Acesse Project Settings → API e copie novamente a Publishable Key.

Parte 3 — EasyPanel (Deploy)

Configuração do servidor, variáveis de ambiente e procedimentos de redeploy

3.1 — Arquitetura do Deploy

O EasyPanel usa o Nixpacks para gerar automaticamente um Dockerfile a partir do nixpacks.toml do repositório. O processo é:

GitHub (push) → EasyPanel detecta mudança
    ↓
Nixpacks lê nixpacks.toml
    ↓
Gera Dockerfile automaticamente (baseado em nixpacks:ubuntu)
    ↓
[BUILD] npm ci (NODE_ENV=development para instalar devDependencies)
    ↓
[BUILD] npm run build (Vite embute VITE_* no bundle JS)
    ↓
[RUNTIME] node server.js (porta 3000)
    ↓
Serve frontend (dist/) + API (/api/send-email)
⚠️
Importante: Build vs Runtime As variáveis VITE_* são embutidas no bundle JavaScript durante o build (disponíveis no navegador). As variáveis GMAIL_* são usadas em runtime pelo Node.js — por isso precisam do padrão || 'fallback' no código, já que o nixpacks pode não as injetar no processo runtime.

3.2 — Configuração do nixpacks.toml

Este arquivo controla o processo de build no EasyPanel. Localizado na raiz do projeto:

# nixpacks.toml
[variables]
# ── Runtime e versão Node ────────────────────────────────────────
NIXPACKS_NODE_VERSION = "20"
PORT                  = "3000"

# ── Supabase (embutidas no bundle pelo Vite durante o build) ─────
VITE_SUPABASE_URL              = "https://hnqzpwxdarllezyhijqh.supabase.co"
VITE_SUPABASE_PUBLISHABLE_KEY  = "sb_publishable_5e8E8brZs6dS08og8slVPQ_durURMQH"
VITE_ADMIN_PASSWORD            = "cajuru@2026"

# ── Gmail SMTP (disponíveis em build, com fallback no código) ─────
GMAIL_USER         = "difernandeszrd@gmail.com"
GMAIL_APP_PASSWORD = "dwouhzqplxqjnfgs"
GMAIL_FROM_NAME    = "Semana Universitária Cajuruense"

[phases.setup]
nixPkgs = ["nodejs_20", "npm-9_x"]

[phases.install]
cmds = ["NODE_ENV=development npm ci"]

[phases.build]
cmds = ["npm run build"]

[phases.caddy]  # Desativa Caddy (conflito de porta)
nixPkgs = []
cmds    = []

[start]
cmd = "node server.js"

C — Fluxo Completo de Envio de E-mail

    ↓
[Frontend - React/Vite]
  → Dados validados no cliente
  → supabase.from('inscritos').insert(dados)   ← grava no banco
  → fetch('/api/send-email', { body: dados })   ← chama o backend
    ↓
[Backend - server.js / Express]
  → Recebe POST em /api/send-email
  → Delega para o handler em api/send-email.js
    ↓
[Handler - api/send-email.js]
  → Lê credenciais (env || fallback)
  → Monta HTML do e-mail de confirmação
  → nodemailer.createTransport({ host: 'smtp.gmail.com', port: 587 })
  → transporter.sendMail({ from, to: email_do_inscrito, html })
    ↓
[Gmail SMTP - smtp.gmail.com:587]
  → Autentica com Senha de App (16 chars)
  → Envia o e-mail para o destinatário
    ↓
[Inscrito recebe e-mail de confirmação]
